# Система motion

Это канонический источник текущих правил движения сайта. Перед изменением
таймингов или добавлением новой анимации сверяться с кодом и этим документом.
Исторические варианты перехода карточки в кейс хранятся в
[`pye-cover-transition-experiment.md`](pye-cover-transition-experiment.md), но
не задают production-параметры.

## Общие правила

- Motion не должен менять смысл или порядок контента: начальное состояние
  должно быть читаемым при отключённой анимации.
- `prefers-reduced-motion` отключает entrance- и shared-cover-анимации.
- Не смешивать две независимые анимации одного элемента. В частности, текст не
  должен сначала появиться обычным образом, затем скрыться и проявиться маской.
- Для перехода карточка ↔ кейс владельцем таймлайна остаётся
  `components/CaseCoverMotion.tsx`; страницы кейсов и `Portfolio` не получают
  отдельных таймеров этого перехода.
- `var(--color-background)` — единый фон главной, кейсов, PYE, 404, footer
  и самого transition layer. Переход не добавляет отдельный цвет фона: под
  маской всегда остаётся тот же токен.

## Главная

### Первое появление карточек

Обычные карточки появляются из `opacity: 0` и `y: 18px` за `560 ms` с
`cubic-bezier(0.16, 1, 0.3, 1)`. Первая строка стартует через `60 ms`, каждая
следующая — ещё через `90 ms`. Это правило не применяется к About в Snakeview.
Пока клиентский React не завершил hydration, `.view-stage[data-view-ready="false"]`
временно держит карточки видимыми; этот fallback не заменяет entrance-анимацию
после готовности клиента и нужен, чтобы задержка hydration не выглядела как
пустая главная.

### Переключение Birdview ↔ Snakeview

Обе раскладки на время перехода остаются в DOM. Они стартуют одновременно,
длятся `320 ms` и используют `cubic-bezier(0.22, 1, 0.36, 1)`:

| Направление | Исходная раскладка | Входящая раскладка |
| --- | --- | --- |
| Birdview → Snakeview | `scale: 1 → 1.1`, `opacity: 1 → 0` | `scale: 0.9 → 1`, `opacity: 0 → 1` |
| Snakeview → Birdview | `scale: 1 → 0.9`, `opacity: 1 → 0` | `scale: 1.1 → 1`, `opacity: 0 → 1` |

Меняется и межстрочный ритм: Birdview `174px → 120px` при входе из Snakeview,
Snakeview `44px → 120px` при входе из Birdview. Названия направления в коде
всегда явные: `birdviewToSnakeview` и `snakeviewToBirdview`.

### About в Snakeview

Текст About раскрывается только горизонтальной маской, без смещения по `x` или
`y`. Строки определяются по фактическому переносу после layout. У каждой строки:

- маска идёт от `-16%` до `100%`, ширина мягкой границы — `16%`;
- длительность зависит от длины строки: `clamp(240 ms, 144 ms + 6 ms × число
  символов, 480 ms)`;
- следующая строка стартует через `7%` длительности предыдущей.

Не добавлять к этим строкам отдельную opacity-анимацию: это создаёт видимое
двухэтапное появление и столбик начал строк.

Telegram-CTA получает отдельное появление после готовности измеренных строк
текста About с фиксированной задержкой `250 ms`, чтобы первый экран не зависел
от количества строк в конкретном viewport. CTA появляется из полной
прозрачности (`opacity: 0 → 1`) и с `filter: blur(12px) → blur(0)` за `350 ms`
с `cubic-bezier(0.12, 1, 0.2, 1)`. Настройка задержки находится в
`components/Portfolio.tsx` (`--hero-about-telegram-reveal-delay`), длительность
— в `styles.css` у `.hero-about__telegram`.

В Snakeview и Birdview первая строка карточек кейсов начинает появляться через
`310 ms`; межстрочный stagger `90 ms` сохраняется.

Поведение CTA после появления — отдельное: на desktop внутренняя зелёная карточка
плавно следует за курсором; на mobile и при reduced motion это выключено.

### Смена языка

Текст локали crossfade'ится за `180 ms` с `easeOut`. Layout-переход карточек
при смене локали длится `240 ms` и использует
`cubic-bezier(0.22, 1, 0.36, 1)`.

## Карточка ↔ обложка кейса

### Вход в кейс

Перед навигацией сохраняются выбранный вид, scroll-позиция и геометрия обложки.
`CaseCoverMotion` держит этот snapshot в памяти provider-а; `sessionStorage`
остаётся fallback для reload и browser Back. Так обратный переход не зависит от
доступности browser storage в обычной client-навигации. Он сохраняет одну
persistent-обложку в transition-слое. После
клика она входит в фазу `preflight` и остаётся на исходной геометрии без
движения, пока новый route не смонтирован. После handoff rect реального target
cover измеряется из DOM два раза подряд; takeover начинается только когда обе
геометрии совпали с допуском менее `0.5 CSS px`. Approximate fallback через
viewport × `16:9` запрещён: target geometry всегда берётся из реального route DOM.

После стабильного измерения обложка начинает движение к destination сразу, за
`640 ms`: `takeoff 280 ms + landing 360 ms`, easing —
`cubic-bezier(0.16, 1, 0.3, 1)`.
Source → target crossfade начинается через `64 ms` уже идущего полёта и длится
`80 ms`. Поэтому разница между изображением карточки и hero-обложкой не даёт
отдельного неподвижного кадра-«моргания» перед движением.
Навигационный handoff задержан только на один frame (`16 ms`), а не на
искусственные `66 ms`. Destination фиксируется перед стартом и не перечитывается,
не пересчитывается и не retarget-ится внутри RAF.
Fixed-layer использует один layout-box назначения и compositor transform
`translate3d + scaleX/scaleY`; `left/top/width/height` не меняются на каждом
кадре.

Источник и target poster остаются отдельными ассетами. Target заранее
зарегистрирован и прогружен невидимо на главной; crossfade начинается только после
готовности target image/video и после первых `64 ms` геометрического движения.
На этапе `preflight` реальная обложка карточки остаётся видимой, пока persistent
layer уже смонтирован поверх неё на той же геометрии; при `landing` layer становится
единственным владельцем изображения.
Незагруженный placeholder не становится финальной hero-обложкой. Если реальный
target не появился или не стабилизировался за ограниченное число кадров,
используется короткий `180 ms` fade-through без неправильной геометрии.

При возврате homepage source cover остаётся скрытым до handoff, а persistent
transition-layer становится единственным видимым владельцем обложки. В обоих
направлениях переключение не образует отдельного визуального кадра. Destination
при возврате берётся из сохранённого source rect и не перечитывается из живого
DOM: canvas не может сдвинуть цель под летящей обложкой.

Для возврата с первого экрана route handoff задержан только на `16 ms` — один
кадр для blur outgoing case shell. С этого же старта homepage canvas идёт одним
полотном из `opacity: 0.33`, `blur(18px)`, `scale(.94)` в `opacity: 1`,
`blur(0)`, `scale(1)`, пока cover мягко приземляется за `400 ms`.
Cover сохраняет быстрый iOS-like `cubic-bezier(0.12, 1, 0.2, 1)`, а opacity,
blur canvas использует более ровный `cubic-bezier(0.4, 0, 0.6, 1)`: blur не
исчезает в первой половине возврата. Масштаб canvas без overshoot сразу идёт
к `scale(1)` вместе с обложкой.
Активная карточка и соседние карточки не имеют собственных delay/animation:
они получают те же CSS variables с корня документа и достигают финального
состояния вместе. Реальная обложка карточки остаётся скрыта до handoff,
поэтому persistent cover приземляется на чёрное место, а не поверх своей копии.
Текст case shell также получает outgoing opacity/blur из этого progress; отдельный
transition не запускается.

После route handoff homepage scroll восстанавливается ещё в двух следующих
animation frame, когда её layout и выбранный view уже применены; transition-layer
и реальная карточка получают один и тот же viewport `top`. На время return
scroll блокируется: пользователь не может сдвинуть homepage под fixed cover,
пока тот ещё летит. Глобальный `scroll-behavior: smooth` также отключён, чтобы
восстановление было дискретным и не продолжало двигать раскладку после handoff.
Handoff через `400 ms` только переключает видимость слоя и не
перезапускает движение.

Пока route кейса монтируется и target rect стабилизируется, `.case-page-shell`
остаётся скрытым, поэтому серверный первый кадр не вспыхивает под общей
обложкой; homepage wrapper при этом не скрывается. После стабильного измерения
route становится видимым, но route-local target cover остаётся скрытым до idle:
видимой остаётся только persistent target image. Заголовок и каждый прямой
блок `.case-content` — текст, одиночное или парное медиа, видео и phone-макет —
начинают общий opacity + лёгкий blur reveal за `112 ms` до конца takeoff, на
`168 ms` от старта полёта. Reveal длится `360 ms`, поэтому контент становится
заметным ещё в движении и достигает финального состояния на `528 ms`, за
`112 ms` до конца полёта. Hero-обложка в этот reveal не входит: она остаётся
единственным владельцем persistent transition-layer до handoff.

Во время forward preflight и landing scroll заблокирован, чтобы измеренный target
rect не устаревал от ручного скролла. Во forward blur вынесен с длинного
`.projects` на viewport-sized fixed backdrop; сама длинная страница больше не
перерисовывается из-за `filter: blur(...)`. Во время короткого return, напротив,
сам homepage canvas получает filter blur: так blur действительно читается вместе
с его scale. Для body-reveal blur применяется к прямым блокам
контента, а не к одному длинному контейнеру кейса. Forward использует
`280/360 ms`; target начинает fade через `64 ms` после старта полёта и остаётся
его геометрическим владельцем до handoff.
Геометрия cover сохраняет canonical return easing без overshoot: cover и canvas
сразу приходят к точной целевой геометрии. Для offscreen-return в Birdview, где
нет видимого исходного rect, persistent cover начинает в центре карточки с
`scale(1.04)` и спокойно сходит к `scale(1)` за те же `400 ms`; это даёт
минимальное движение вместо неподвижного появления. Snakeview этот fallback не
использует. Возврат на главную сохраняет canonical geometry `400/416 ms`; homepage cover остаётся непрозрачной в persistent layer,
а route-local cover скрыта до точного handoff. Поэтому возврат не создаёт
двойную картинку, прозрачную дыру или мигание.

### Возврат на главную

Этот переход — canonical motion reference сайта: плавное приземление карточки,
синхронное снятие blur и мягкое появление контента. Landing cover длится `400 ms`
с `cubic-bezier(0.12, 1, 0.2, 1)`. Весь остальной первый экран появляется за ту
же длину, но с ровным `cubic-bezier(0.4, 0, 0.6, 1)` для opacity и blur: canvas
`scale(.94 → 1)`, `opacity(.33 → 1)`, `filter: blur(18px → 0)`, outgoing case shell —
`opacity(1 → .6)`, `blur(0 → 12px)`. Реальная обложка карточки скрыта, пока
persistent cover не достигнет той же geometry. Поэтому обложка и сетка достигают `100%`
в одном handoff, без двойника картинки или отдельных 450/350/350+150 clocks.

При видимой обложке homepage cover летит из сохранённой геометрии кейса в
геометрию карточки; при глубоком scroll или если source cover нельзя измерить,
используется локальный fallback активной карточки без отдельного полёта. В обоих случаях
первое media-изображение кейса не подменяет родную homepage cover. Точка scale
полотна рассчитывается в центре viewport, а не в центре длинного scroll-полотна.

Если обложка кейса вне viewport, используется локальный fallback активной
карточки: persistent homepage-cover показывается сразу без отдельного полёта,
а общий landing полотна продолжается за `400 ms` с тем же canvas reveal.

## Карта владения

- `components/Portfolio.tsx` — entrance главной, смена view/locale, About и CTA;
- `components/CaseCoverMotion.tsx` — snapshot, фазы
  `preflight`/`landing`/`handoff`/`fallback`, навигация и shared-cover;
- `components/LocaleTextTransition.tsx` — crossfade локализованного текста;
- `styles.css` — CSS-маски, blur/opacity и reduced-motion-исключения.

## Проверка после изменения motion

1. Проверить первый кадр: контент не должен мигать или появляться дважды.
2. Проверить оба направления Birdview ↔ Snakeview и `EN ↔ RU`.
3. Проверить вход и возврат из кейса в обоих видах, включая возврат после
   глубокой прокрутки.
4. Проверить desktop, mobile и `prefers-reduced-motion`.
5. Выполнить `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` и
   `git diff --check` в зависимости от затронутого кода.
